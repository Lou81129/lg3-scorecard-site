Bug Fixes — Back Panel Headers, CTP, Card Sizing (v96.12)

Bug 1 — Scarlet Section Headers Invisible on Back Panel

The SHAMBLE FORMAT RULES and CLOSEST TO THE PIN — CTP section headers on the Shamble card back panel rendered as invisible — dark red bars with no visible text.

  • Root cause: a second .bst { color: #000 !important } rule in the CSS sheet was overriding the inline color: #fff on the scarlet header bars, forcing text to black on a dark red background
  • Fix: added new .bst-sc class with explicit !important white-on-scarlet styling; applied to both back panel section headers

Bug 2 — CTP Section Contained Unnecessary Fields

The Closest to the Pin section showed Player: _______________ Dist: ______ fields for each hole, which are not needed on the card — the CTP section only needs to indicate which holes are in play.

  • Fix: Player and Distance fields removed; section now shows four clean checkboxes: Hole 2 (Par 3), Hole 9 (Par 3), Hole 13 (Par 3), Hole 17 (Par 3)

Bug 3 — Shamble Card Width Mismatched Scramble Card

The Shamble card used hardcoded tc.style.width = '10.25in' and tc.style.height = '3.75in' inline overrides that conflicted with the #team-card CSS dimensions used by the Scramble card.

  • Fix: inline width/height overrides removed; Shamble card now inherits #team-card CSS dimensions, matching the Scramble card on the same card stock

PAR/HDCP Subtotals & Course Name in Header (v96.13)

PAR Row — OUT, IN, TOT Pre-Filled

The OUT, IN, and TOT subtotal cells in the PAR row were rendering as empty gray boxes. The Scramble card fills these correctly; the Shamble card did not.

  • Fix: outPar and inPar totals computed from course profile and inserted into the respective subtotal cells; TOT = outPar + inPar

HDCP Row — Dashes in Subtotal Cells

The OUT, IN, and TOT cells in the HDCP row were also blank. These cells have no meaningful value, but should display a dash for visual consistency with the regular card.

  • Fix: subtotal cells now display an en dash (–) in all three positions

Course Name Added to Shamble Card Header

The Shamble card header bar showed only LG3 · SHAMBLE TEAM CARD with no course name — unlike all other card types which include the course.

  • Fix: course name pulled dynamically from the course-select dropdown and appended to the header: LG3 · SHAMBLE TEAM CARD · Tampa Palms G&CC

Full-Width Table & Game Dropdown Order (v96.14)

White Space Gap on Right Side of Card

The Shamble table left a visible white gap on the right side where the P3G/P3N columns would normally appear on a stroke play card. The fixed-inch colgroup summed to only ~10.27in, leaving ~0.73in unused on an 11in card.

  • Fix: switched from fixed-inch colgroup to percentage-based layout — label column 14%, each of 21 data columns 4.095% — totalling 100% and filling the full card width
  • Hardcoded width: 1.45in also removed from the label cell style; colgroup percentage now controls it

Game Dropdown — Default and Alphabetical Order

The Team Game dropdown did not have a default "select" option and listed games in an inconsistent order (Scramble → Chapman → Shamble).

  • Fix: dropdown now defaults to — Select Game —
  • Games listed in alphabetical order: Chapman → Scramble → Shamble
  • Saved game restore logic (_savedGid) preserved — selection persists through setup field changes

Design — Fold Gutter & High-Contrast Text (v96.18)

Fold Gutter — First Implementation

Physical fold testing showed hole 9 data was being lost in the card crease. The Shamble card needed a visible fold guide like the standard stroke play card.

  • OUT column width increased from equal-width data column to 7% (nearly double) — pushes front nine left
  • All hole 10 cells given a 4px solid scarlet left border — visible fold line across every row
  • Applied to: HOLE, PAR, HDCP, all four player rows, Drive Used, and all three Team Score rows

High-Contrast Text — Senior Readability

Print testing with senior golfers revealed that gray text on light gray backgrounds was very difficult to read. The PMS 429 gray (#A7B1B7) was being used as foreground text color in addition to backgrounds.

  • Introduced new dark text constant DK = '#1A1A1A' (near-black)
  • DK replaces GR (#A7B1B7) everywhere it was used as a foreground text color
  • PMS 429 gray retained for backgrounds and borders only
  • Affected elements: PAR values, HDCP values, player tee/PH sub-labels, Drive row label, info bar text, dot markers

Bug Fix — Stableford 15/20 Card Row Misalignment (v96.19)

The 15/20 Balls Stableford scorecard rendered with rows visibly misaligned — player score rows on the left panel appeared to sit opposite the Points rows on the right panel and vice versa.

  • Root cause: the right-panel table (tbr) appended its rows in reverse order compared to the left-panel table (tbl). Left table: score row first, then Points row. Right table: Points row first, then score row — causing every player's rows to be swapped across the fold
  • Fix: swapped tbr.appendChild(_sfR) and tbr.appendChild(rpr) — right table now appends score row first, Points row second, matching the left table order exactly

Design — Shamble Card Fold Gutter Rework (v96.21–v96.23)

The fold gutter introduced in v96.18 (a wider OUT column + scarlet border) was replaced across three iterations with a more robust implementation that produces a true physical fold line identical to the standard stroke play card.

v96.21 — Two-Table Flex Architecture (Intermediate)

  • Split Shamble card into two separate <table> elements in a flex container, with a 6px solid scarlet <div> panel separator between them — matching the structural approach of the stroke play card
  • Left table: label + holes 1–9 + OUT; Right table: holes 10–18 + IN + TOT
  • Issue discovered: section divider rows (PLAYER SCORES, DRIVE USED, TEAM SCORE) had text content on the left and empty counterparts on the right, causing row height drift that cascaded into visible misalignment

v96.22 — Single-Table 23-Column Architecture

  • Root cause of v96.21 misalignment: separate tables have independent layout engines — row heights cannot be synchronized across them
  • Solution: rebuilt as a single table with 23 columns, including a dedicated scarlet gutter column between OUT and hole 10
  • Column layout: label (14%) + 9 holes + OUT + gutter (0.5%, background: #BA0C2F) + 9 holes + IN + TOT = 100%
  • Section divider rows span all 23 columns via colspan="23" — no matching-row issue possible
  • Gutter cells include -webkit-print-color-adjust: exact; print-color-adjust: exact to ensure scarlet prints correctly
  • All rows guaranteed to align since they share the same table layout context

v96.23 — Label Column Narrowed for Centered Fold

With a 14% label column the gutter landed at approximately 6.05in — visibly to the right of the 5.5in card center. Narrowing the label column moves the gutter toward center.

  • Label column: 14% → 8% (1.54in → 0.88in)
  • Data columns: 4.071% → 4.357% (wider, to fill the reclaimed space)
  • Gutter center: 6.05in → 5.70in — 63% closer to the 5.5in fold
  • Player name font adjusted: 11pt → 10pt to fit narrower label cell
  • Team score labels adjusted: 11pt → 9pt
Note: Mathematical perfect centering (5.5in) is not achievable with a single-table layout and any practical label width — it would require a label column of ~0.5in, too narrow for player name text. The 5.70in gutter position represents the optimal balance between centering and label legibility.
